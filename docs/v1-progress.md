# V1 개발 진행률 운영

2026-09-08 조사: 별도 설계도, 요약본, 로드맵, 엔진 명세, 테스트 시나리오 문서는 프로젝트에 없었습니다. 기존 app/**/page.tsx의 purpose와 메인 구성요소를 근거로 10개 제품 모듈을 임시 분류하고, 이번 사용자 요청에 따른 패널 모듈 1개를 추가했습니다. 공식 V1 범위 확정본이 아닙니다. 문서 확보 시 모듈과 조건을 대조하세요. 단순 준비 중 화면은 기능 PASS가 아닙니다.

## 갱신 순서
1. lib/v1-progress.ts에서 대상 모듈의 phase를 작업중으로 지정합니다.
2. 기능 구현 후 각 criterion.label에 해당하는 동작을 실제 테스트합니다.
3. criterion.result를 PASS / FAIL / 미검증으로 기록합니다. 테스트한 항목에는 evidence(재현 절차·결과)와 testedAt(날짜)을 함께 기록합니다.
4. 미테스트 항목은 미검증으로 남깁니다. 관련 코드 변경으로 기존 증거가 유효하지 않으면 미검증으로 되돌리고 다시 테스트합니다.
5. 저장 시 Next 개발 서버의 갱신으로 패널에 반영됩니다. 브라우저에서 체크를 클릭해 완료로 바꾸는 기능은 없습니다.
6. 매 작업 완료 시 새 V1 모듈이나 기존 범위 변경 여부를 확인하고, 해당 모듈·완료조건·관련 페이지·근거 파일을 함께 최신화합니다. 새 조건은 미검증으로 시작하며, 기존 PASS는 변경된 범위에도 증거가 유효할 때만 유지합니다. 범위 변경이 없으면 모듈을 임의로 추가하지 않습니다.

모듈 진행률 = 증거와 날짜가 있는 PASS 수 / 모듈의 모든 조건 수 × 100 (내림).
전체 진행률 = 모든 모듈의 검증 PASS 수 / 모든 조건 수 × 100 (내림). 모듈 퍼센트의 평균을 사용하지 않습니다. 보류 조건도 분모에 남습니다. 조건 0개는 0%·미검증입니다. FAIL이 하나라도 있으면 검증 결과는 FAIL, 모든 조건 PASS일 때만 PASS입니다.
모듈 상태는 phase(미착수/작업중/검증중/보류)를 기본으로 하되 모든 조건 PASS면 완료로 자동 표시됩니다. 명시적 보류는 유지합니다. 다섯 상태의 모듈 수를 각각 표시합니다.

## 구조와 제거
- lib/v1-progress.ts: 모듈 목록, 검증 증거, 순수 계산 함수
- components/dev/v1-progress-panel.tsx 및 CSS Module: 독립 UI
- app/layout.tsx: 전역 장착 한 곳. Link 이동에서 열림·아코디언 상태 유지. 새로고침 시 기본 접힘(모바일 포함).
- 제거: layout의 import와 V1ProgressPanel 한 줄 제거 후 전용 파일 삭제. 기존 기능 의존성 없음.
- 관련 페이지는 실제 로컬 경로 링크, 근거 소스는 파일 경로로 표시합니다. 공식 설계 문서가 추가되면 sources에 등록하세요.

패널은 요청에 따라 모든 환경에서 표시됩니다. 공개 배포 전에 필요에 따라 layout에서 제거하세요.
